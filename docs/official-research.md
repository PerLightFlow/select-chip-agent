# 官网资料查询与导入

本模块提供链接导入、官方目录发现、资料不足时的自动查询，以及可选的周期变化检查。原始文件、文档版本和待核验参数进入同一个公共知识库；只有审核发布后的文档与已确认参数参与正式选型。

## 页面操作

1. 管理员打开“官网资料”，粘贴产品页、PDF 或官方文档 HTTPS 地址，点击“导入官网链接”。普通用户可使用“查询官网”查询官方资料。
2. 任务由已有 worker 后台处理。网页显示排队、查询、完成或失败；离开后可在“最近联网任务”查看。任务记录按创建账号访问，知识库审核发布后共享。
3. 展开原文摘录及参数建议，可下载原始抓取快照或访问官网。自动提取需要配置 LLM；模型不可用时仍保存原文。参数建议只是草稿，不是已经通过的选型依据。
4. 管理员通过“核验与发布”检查 DocumentVersion：原文、型号适用范围、SDK、表格、脚注及单位。自动填写的型号与 SDK 仅为提示，必须核对。
5. 配置 Embedding 后，抓取成功会自动排队建立索引。未配置时保存 draft；配置完成后在后台执行“生成待审核索引”。仅在主动接受降级时设置 ALLOW_KEYWORD_ONLY=1。
6. ready 状态允许修改适用型号、SDK 与任务元数据。正文或文件需要修改时新建版本。审核发布文档后，创建或确认对应的 Chip。
7. 逐项核验参数建议后，执行“已逐项核验：采纳无冲突参数建议”。只有原文引用能定位到当前已发布 Chunk、适用型号正确且 Chip 已存在的建议可采纳。已有参数不会被覆盖；冲突详情记录在 AuditEvent，管理员可另行审阅 Fact。新芯片不会自动变成在售或已发布。
8. 再次运行项目选型使用更新后的知识库。历史选型报告不会自动重写。

在选型工作台或文档检索勾选“资料不足时自动查询官方来源”，没有候选、缺少参数证据或任务适配资料时自动创建查询任务。演示模式不触发联网。查询完成的待核验资料与原有选型结果分开展示，不会改变当前硬约束判断。

## 来源与发现方式

来源清单位于 backend/core/official_sources.json，可通过代码评审扩展厂商。默认允许乐鑫和瑞芯微的指定官网、文档站，以及 GitHub 的 espressif、airockchip、rockchip-linux 组织路径；不采集 GitHub 用户讨论和拉取请求页面。

发现方式为：读取配置的官方产品目录和 SDK 仓库首页，依据型号及关键词选择相关链接继续读取。最多访问 8 个页面、深度 2，保存最多 3 份候选资料；不依赖收费搜索 API。关键词有少量中英文映射，精确型号不与相近后缀型号混用。

这是有界的官方目录发现，不是全网搜索。目录链接缺失、动态渲染、访问限制或查询表达差异可能导致漏检；此时可由管理员直接导入准确的文档链接。官网目录的存在不能证明型号仍在售，不能据此宣称全量覆盖。

SDK 输入也是检索提示，抓取到的文档可能不是该 SDK 版本，必须核对。参数抽取最多处理前 20000 字符，保留完整原件；跨页表格、复杂合并单元格和扫描件仍需人工处理。当前提取结构化芯片参数；算子适配和条件化算法基准仍沿用管理后台录入，不自动得出实时性承诺。

## 更新检测

同一来源内容 SHA-256 相同则复用原版本；内容变化则保存新版本，不切换 active_version。管理员审核发布后才切换检索证据。已撤回版本不会因为再次抓到同样内容而自动重新发布。

在后台 OfficialSource 设置 refresh_hours（0 关闭，正整数为间隔小时），现有 worker 会排队检查到期来源；默认所有来源为 0，不执行周期联网。管理员也可选择“检查官网是否更新”。检查使用内容哈希，不依赖不可靠的 Last-Modified；目前每次重新下载，无条件 HTTP 缓存优化。间隔按排队时间计算，不是精确定时调度。

## 接口

| 接口 | 作用 |
| --- | --- |
| GET /api/official/sources/ | 来源范围及开关状态 |
| POST /api/official/jobs/ | 创建 search 或 import 任务；import 要求管理员 |
| GET /api/official/jobs/ | 当前账号最近 30 个任务 |
| GET /api/official/jobs/{id}/ | 任务进度、摘录、参数建议和错误 |
| GET /api/official/jobs/{id}/files/{version_id}/ | 下载该账号任务的原始文件快照 |
| POST /api/search/ | auto_online=true 时，在无结果时触发官网查询 |
| POST /api/projects/{id}/runs/ | auto_online=true 时，在资料不足时触发官网查询 |

相同账号和查询 15 分钟内去重（失败可重新提交）；每账号最多 3 个待处理任务、20 个新任务/小时。返回的 job_id 可轮询，前端每 2.5 秒读取一次，完成后停止。

## 运行与验证

新增配置 OFFICIAL_ONLINE_ENABLED=1；设为 0 关闭自动查询、导入执行和周期检查。无需新增模型密钥或搜索服务密钥；参数提取沿用现有 LLM，索引沿用现有 Embedding。

更新并重建容器：

    docker compose up --build -d

backend 启动时应用迁移，worker 与 backend 使用同一数据库和文档卷。来源需要部署机器可以直接访问公共 HTTPS；采集器不继承环境代理、浏览器 Cookie 或登录信息。

HTTP 层逐次验证白名单和重定向，解析 DNS 后拒绝非公网地址，并连接校验后的 IP，保持原域名 TLS 证书验证。遵守 robots、请求间隔、大小限制和抓取预算；失败原因对用户可见。需要登录或被禁止抓取的资料使用既有人工上传流程。

自动化测试覆盖 URL/DNS/重定向边界、robots、大小上限、版本去重、更新不覆盖、参数引用验证、冲突审核、任务归属、自动回退、调度以及浏览器入口。CI 另保存 official-source-probe.json 作为真实公网可达性诊断；诊断失败不等于单元测试失败，也不会被宣称为成功抓取。

可手动运行：

    cd backend
    python probe_official.py

本机无法联网不影响已有知识库检索；官网失败不能被解释为芯片不支持某能力。
